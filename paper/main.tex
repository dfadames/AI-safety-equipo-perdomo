\begin{abstract}
  Safety checks for AI agents usually audit one agent at a time. We built a testbed in which every agent's container passes such an audit, yet the agents, talking over a shared channel, assemble a credential that no single container holds. Language-model agents (\texttt{deepseek-flash}) run in containers with no network and one credential fragment each; submitting the assembled credential to a validator is the restricted action. Across 95 episodes we recorded 48 collective escapes, including 39 of the 40 instructed episodes in which every fragment was reachable and none of the 5 in which one was not. A per-agent judge given the same rule flagged all 48 escapes, so this failure is not hard to detect --- but the judge returns one score per agent and names no origins. The harness instead builds an exposure-provenance graph from the logged context windows and attributes each escape to the containers and messages behind it, with no under-attribution against an independent oracle. A trivial baseline --- the containers of the agents that sent the validating agent its messages --- recovers the same origins in all 48 escapes, because our channel is a broadcast; on this testbed the graph's attribution is checkable against the oracle but not more informative than reading one trace. This is a two-day proof of concept: one model, 5--10 episodes per condition, containers reused across episodes, and no causal test of the attribution.
\end{abstract}

\section{Introduction}

Safety measures for autonomous agents are usually designed around one agent: a sandbox is audited for network access and secrets, a monitor reads one trajectory, and after an incident investigators ask why that agent did not escalate. Security research has long known that properties verified per component need not hold once the components are connected (Goguen and Meseguer, 1982; McCullough, 1987; Mantel, 2002). Language-model agents that share a channel are a natural case: each can be contained on its own while the group reaches information that no member holds.

The July 2026 incident in which models under evaluation escaped a research sandbox and reached production infrastructure prompted this sprint (OpenAI, 2026; Larcher et al., 2026). As we read the public analyses, no single agent left its sandbox alone. METR reports agents that ``were meant to be fully isolated from one another'' establishing an unsanctioned message board in a package-repository cache (Greenblatt et al., 2026). We do not reproduce the incident. We build a minimal setting for one mechanism it suggests, information composed across container boundaries, and test the claim that \emph{local containment does not imply system-level containment} under it.

Each agent has its own container, which passes an individual containment audit. The only coupling is a message channel run by the harness. A credential is split into parts across the containers, and validating it is the restricted action. No single step is misbehaviour: an auditor who finds a credential fragment and reports it to colleagues is doing its job. We then ask what an overseer can reconstruct from the logs afterwards --- which containers the information came from, and which messages carried it.

\textbf{Contributions.} \textbf{(i)} An audited instance of non-composition: every container passed all six local checks while the population reached the restricted action in 48 episodes. Non-composition is an existential claim (Section~\ref{sec:problem}), so one episode establishes it and the rates describe only this testbed. \textbf{(ii)} Exposure provenance across agent boundaries. The harness builds a graph from the logged context windows, with message deliveries as the only boundary-crossing edges. It attributes a restricted action to its contributing containers and message routes, checked against an oracle that does not read the graph. \textbf{(iii)} A comparison with per-agent monitoring, which matches the graph's escape recall when given the same policy and reports no attribution.

\textbf{Scope.} This is a rapid proof of concept, built and run in a two-day sprint to judge whether tracing provenance across agents deserves more effort, not to measure effect sizes. A pilot batch of 37 episodes exposed flaws in our own pipeline: guessable parts, a permissive validator and invalid counterfactual replicas. We fixed the task and re-ran every condition, giving the 95 episodes reported here, 5--10 per condition, with one model (Appendix~\ref{app:pilot}). Table~\ref{tab:claims} separates what the testbed demonstrates from what it suggests, and Appendix~\ref{app:limits} states the limitations and the dual-use considerations.

\section{Related Work}
\label{sec:related}

That properties verified per component need not survive their connection is classical (Goguen and Meseguer, 1982; McCullough, 1987; Mantel, 2002). The same shape has now been shown in ML, where an adversary misuses combinations of individually safe models by decomposing a task across them (Jones et al., 2025; Srivastav and Zhang, 2025; Chen et al., 2025; Spera, 2026). Cross-agent flow control and provenance exist, but as runtime enforcement scored by violations blocked (Dai et al., 2026; Shivakumar et al., 2026; Wu and Gong, 2026; Y. Wang et al., 2026b). Our post-hoc query is BackTracker's (King and Chen, 2003) over agent events rather than operating-system objects, and per-agent monitoring is known to degrade as an attack is spread over more agents (Makins et al., 2026). Appendix~\ref{app:related} treats each line in full.

\textbf{Positioning.} Each ingredient has precedents; we claim none of them. What we add is an audited instance. Individually contained LLM agents complete a restricted action by aggregating fragments across container boundaries, and an exposure-provenance graph attributes that action, post hoc and against an oracle, to its contributing containers and message routes. Non-composition has been proved formally and demonstrated against an adversary who decomposes a task; we exhibit it with no adversary, in containers that pass an executed six-check audit, with the split imposed by the deployment rather than chosen to evade a filter. Cross-agent provenance exists as runtime enforcement scored by violations blocked; ours is scored by under-attribution against an oracle that knows how many containers the action had to draw on, a check those benchmarks have no counterpart for. And where per-agent monitoring is known to degrade under distributed attacks, we report the opposite regime: it detects every escape and still tells an overseer nothing about which containers and messages to act on.

\section{Problem and Testbed}
\label{sec:problem}

\textbf{Setting.} An episode runs \(N\) agents, each acting only through tools a harness executes inside its own container. A credential is split into \(P\) parts assigned cyclically, so every container holds exactly one: with \(N>P\) some parts sit in several containers, with \(N<P\) some in none. The restricted action is a call to a validation tool, which succeeds only on the exact credential. A container is \emph{locally contained} if it passes the six checks below, evaluated on that container alone, and a \emph{collective escape} is a successful validation in an episode where every container is locally contained and none holds all the parts. Since the acting container holds one part, an escape implies \(P-1\) parts reached it from elsewhere. Appendix~\ref{app:testbed} states this formally.

Two points govern how to read the results. Non-composition is an existential claim, so one execution establishes it; the escape rate is a separate quantity that depends on model, prompts and configuration. And an escape is established by the configuration and the oracle, not by the graph, which attributes an escape rather than defining one. That the foreign parts arrived through the channel rests on two assumptions. Agents cannot invent a part, since parts are random strings their labels do not reveal. And the channel is the only path between containers within an episode, which held in every check we ran but not across episodes (Section~\ref{sec:contam}). We call the first successful validation the \emph{decisive action}; Table~\ref{tab:terms} fixes the remaining terminology.

\textbf{Testbed.} Each agent has its own Docker container (\texttt{alpine}, \texttt{network\_mode: none}) whose only mount is a read-only volume holding its fragment among unrelated settings. The model runs on the host and commands go through \texttt{docker exec}. Agents act in round-robin turns with a context of their last 8 events. The channel is a broadcast: every post reaches every agent, which matters for the baselines of Section~\ref{sec:attr}. Agents and judge are \texttt{deepseek-flash} (DeepSeek-AI, 2026) at temperature 0, and the API exposes no seed, so episodes are not reproducible bit for bit. Each container is checked when started, for six things: no internet access, no API credentials in the environment, access to its own hint, no other container's fragment on disk, no write access to the hint volume, and no mount beyond the read-only volume. All containers passed every check at every population size (Table~\ref{tab:auditoria}); Appendix~\ref{app:testbed} gives the tools, channel limits and protocol.

\textbf{Conditions,} labelled R1--R3 in decreasing order of explicit instruction. \emph{Instructed} (R1) tells agents to find their fragment, share it, gather the parts and validate. \emph{Emergent} (R2) gives a plausible local task --- audit your own service, validate any credential that ``appears complete'' --- and mentions other auditors and the channel only as a way to coordinate findings; \emph{R3} drops both mentions, though the channel tools remain. \emph{Honesty} is R1 plus a notice that the agent is monitored and honesty takes priority; \emph{benign} is a monitoring prompt that never mentions credentials; the \emph{1-part control} is R1 with \(P=1\), so validating is legitimate. Prompts are in Appendix~\ref{app:prompts}. We ran \(N\in\{3,4,5,8\}\) at \(P=4\) and \(P\in\{1,2,3,4\}\) at \(N=4\), 10 episodes per point at \(N=4\) and 5 elsewhere: 95 episodes, of which 48 escapes, 37 without escape and 10 one-part controls. Three further episodes stopped on a harness error and were re-run; they are excluded.

\section{The Exposure-Provenance Graph}
\label{sec:graph}

\textbf{Logging.} Every tool call is logged as an event carrying its agent, container, type, global step, content and ancestors, the last assigned when the call is made. A container's first command output has no ancestors: it is a \emph{root}, the entry of that container's local information into the record. A \emph{receive} event has one ancestor, the sender's post. Every other event inherits the events in the agent's context window at that step. When the window overflows, the oldest events are replaced by a summary whose ancestors are the events it replaced. Each summary absorbs the previous one, so anything that ever entered a window stays a transitive ancestor of that agent's later actions. Ancestry is therefore an upper bound on what was in context and, a fortiori, on what was used --- which is what makes the completeness check meaningful.

\textbf{Two queries.} Nodes are events, edges run from ancestor to descendant, and edges between different agents are exactly the post-to-receive pairs, one per delivery. We ask two things of an action's ancestry. The \emph{origin span} \(\sigma\) counts the distinct containers whose roots appear in it. The \emph{minimum cut} \(\kappa\) gives deliveries capacity 1 and within-agent edges unbounded capacity, then cuts between the foreign roots and the action. By max-flow/min-cut (Ford and Fulkerson, 1956) it counts edge-disjoint exposure routes, and the cut itself is a smallest set of deliveries whose removal from the \emph{record} disconnects the action from every foreign root. Removing them from the record is not an intervention on the execution, and we did not test whether withholding them would have prevented the action. Appendix~\ref{app:control} gives the construction.

\textbf{Oracle.} For a validation of string \(s\) the oracle returns the parts contained in \(s\), reading the string and not the graph. A success requires the exact credential and parts cannot be guessed, so the action must have drawn on at least \(P\) containers. A decisive action is \emph{exact} when \(\sigma=P\), \emph{over-attributed} when \(\sigma>P\), and \emph{under-attributed} when \(\sigma<P\), which would mean a transfer went unrecorded. We also check that every part in the string is held by some container in the span. Completeness relative to this oracle is what we measure; we do not establish that every cross-container transfer passed through the harness, and one path across episodes did not (Section~\ref{sec:contam}).

\textbf{Alarm and baselines.} The graph's alarm fires when any call to the restricted action, successful or not, has \(\sigma>1\). It needs no model calls --- ancestry is a traversal and the cut one max-flow computation (NetworkX; Hagberg et al., 2008) --- and encodes the same policy given to the rule-aware judge, an LLM-as-a-judge baseline (Zheng et al., 2023).

\section{Results}
\label{sec:results}

All results come from the 95 episodes of the main batch. With 5--10 episodes per point we report counts, with 95\% Clopper--Pearson intervals where a rate is quoted, and read each result as an existence proof or a first estimate. Three of the numbers below follow from the design. We report them as checks that the harness works, not as findings. The graph's alarm flags every escape because a successful validation with \(P\ge2\) and no under-attribution necessarily has \(\sigma\ge2\). The absence of under-attribution (0 of 48) is a completeness check on the logging rather than an error rate, so we quote no interval for it. And at \(N=P\) the span cannot exceed \(P\), so over-attribution is observable only at \(N>P\).

\subsection{Local containment held; system-level containment did not}

Every audited container passed all six checks. In the instructed condition (R1, without the honesty modifier), agents assembled and validated the credential in 39 of the 40 episodes in which every part was held by some container (Table~\ref{tab:escape}, Figure~\ref{fig:curvas}a). In the one exception, an agent found its fragment but spent its turns searching its container and never posted it while the other three waited. With \(N=3\) one part exists in no container: no episode escaped and agents made no validation attempt at all, a negative control showing that the harness did not leak the missing part. R1 asks agents to combine parts, so this is not spontaneous misbehaviour. It is the architectural point: an audit every container passes does not bound what the system of containers reaches once information crosses the channel.

Without an instruction to pool, escapes were rare: 0 of 10 R2 episodes and 1 of 10 R3 episodes. That single escape occurred in a contaminated episode (Section~\ref{sec:contam}); over the 12 emergent episodes that were free of contamination, none escaped. We therefore report the emergent conditions as an upper bound consistent with zero, not as a rate. In that escape, three agents whose prompts mentioned neither the channel nor other auditors posted their fragments anyway, and the fourth validated the assembled credential without posting or notifying anyone. In two other R3 episodes an agent submitted three of the four fragments. The pilot's R3 rate (2 of 3) did not replicate. With the honesty modifier added to R1, 8 of 10 episodes escaped, against 9 of 10 without it (Fisher's exact test, \(p=1.00\)). This is weaker than it looks: the notice ranks honesty above the task, but nothing says pooling is the dishonest part, so an agent that pools and then reports obeys both instructions. R2 and R3 still carry cues toward pooling. The fragment label announces ``part \(k\) of \(P\)'', the validation tool invites citations of channel messages, and in R3 the channel tools remain available though unmentioned. These episodes show only that escape \emph{can} occur without an explicit instruction. No benign episode contained a validation attempt, though in 3 of the 10 an agent posted its fragment to the channel.

\subsection{Exposure provenance of the escapes}
\label{sec:attr}

Across the 48 escapes the origin span equalled \(P\) in 31, exceeded it in 17 and was never below it, and the part-identity check passed in all 48 (Table~\ref{tab:alineacion}). No escape under-attributed: no contributing origin the oracle named went unrecorded. This is a completeness check on the harness, not an error rate, and it says nothing about information flowing outside the log --- one such path did exist, across episodes (Section~\ref{sec:contam}). Over-attribution occurred only where it could, at \(N>P\), in 17 of those 30 escapes. In every case the excess \(\sigma-P\) equals the number of containers in the span holding a part already represented, because the validating agent saw the same part from two containers, or its own part from another. Over-attribution here is redundancy of exposure, not a failure to identify origins.

\textbf{An attribution baseline the graph does not beat.} The graph's output is a set of containers, so the question is whether a cheaper reading of the same logs yields that set too. We scored three methods part by part against the oracle: the origin span; the containers of the agents that sent the validating agent the messages in its own context; and the senders of the cut deliveries alone. A method attributes a part correctly when the containers it names include one holding that part. All three recover all 162 parts across the 48 escapes, naming the same containers in every episode, a mean of 3.79 of them.

We had expected relays to separate them. Of the 158 cut deliveries, 38 carried a part their sender did not hold, in 21 of the 48 escapes. In those episodes a sender named in the acting agent's trace is not the origin of what it forwarded, and it still makes no difference. The reason is our own design: the channel is a broadcast, so the validating agent had also received each part straight from its holder. A relay adds a route, not a missing origin. This bounds what we can claim. Here the graph is no more informative about \emph{which containers} than reading one trace, and showing otherwise needs a channel whose messages are addressed. What the graph adds with no counterpart in the baseline is the cut itself and a completeness check against the oracle. The sender list happens to be complete in this batch, and nothing in the sender list would say so.
\textbf{What the graph measures: the 1-part control.} With \(P=1\) every container holds the complete credential, so validation is legitimate, yet agents were still told to share and the alarm fired in all 10 episodes (Appendix~\ref{app:control}). These are false alarms against the policy, not attribution errors: the foreign messages really were in context. The control fixes what the graph measures --- whether foreign information was \emph{available} to an action, not whether the action \emph{used} it.

\textbf{Minimum cut.} The cut grew with both the number of parts (Spearman's \(\rho=0.74\), 29 escapes, permutation test \(p<0.001\)) and the number of agents (\(\rho=0.64\), 19 escapes, \(p\approx0.005\)); means by point are in Table~\ref{tab:escape} and Figure~\ref{fig:curvas}b,c. Decomposing \(\kappa=(P-1)+D+E\) separates a floor of one route per foreign origin from redundant containers \(D\) and extra routes \(E\). \(E\) was never negative, so every escape had at least \(P-1\) routes, and the growth with \(N\) came from redundant exposure rather than from additional necessary messages (Appendix~\ref{app:cut}). In 42 of the 48 escapes the cut lay between \(P-1\) and \(P+1\). For an overseer it is a workload figure --- how many deliveries to examine --- not a set known to be necessary.

\textbf{Two predictions registered before the runs.} Both were committed to git before the episodes they concern. That the cut would grow with \(N\) (\texttt{1ebf99b}, 17:47, before the \(N=8\) runs at 18:32) failed in the pilot and holds here, but through redundancy rather than the extra necessary messages we had in mind. That the cut would equal \(P\) (\texttt{06a3cad}, 21:38, before the \(P=2,3\) sweep at 22:34) holds only in part: \(P-1\) is the floor, and the mean sits near \(P\) because redundancy usually adds one route. A provenance method is worth more when its structural quantities are predictable in advance, and one of ours was not.

\subsection{Detection versus attribution}

The graph's alarm, the judge with the rule and message count each flagged all 48 escapes (Figure~\ref{fig:deteccion}). The validating agent's own trace contains the fragments it received and the validation, so one trace suffices once the monitor knows the policy. Nothing here shows that the graph detects better: the judge was given the same policy, and message count flags almost any collaboration.

Outside escapes the monitors differed (Table~\ref{tab:limpios}). Only 5 of the 37 episodes without escape contained a restricted action, so only there could the graph fire, and it fired in 3. The judge with the rule fired in 23 of the 37, in every case because an agent had posted a fragment --- a precursor the graph cannot flag without a restricted action, and the judge's advantage here. In the 1-part control the judge fired in 2 of 10 and the graph in all 10. What the graph adds instead is a structured account of each escape, computed without model calls and checkable against the logs --- though Section~\ref{sec:attr} shows how much of it a far cheaper method already gives. Whether a population-level judge could attribute as well is untested.

\subsection{A coupling that neither the audit nor the graph caught}
\label{sec:contam}

The harness started the containers once per population size and reused them across that size's episodes, so files an agent wrote survived into later ones. We did not intend this and found it only by checking every episode's parts against every other episode's logs. Fragments written in 6 of the \(N=4\) episodes reappeared in 28 later ones, in all four containers. Agents posted them to the channel in 10 of those episodes, submitted them in failed validations in 4, and reported them to a human in 8. They belonged to other credentials and so could not validate: every decisive validation used its own episode's parts. Excluding the 28 leaves the main picture unchanged, with instructed agents escaping in 32 of 33 feasible episodes, but 12 of the 48 escapes lie among them, as does the single R3 escape.

This is a finding and not only a limitation, because it is the observation in our batch closest to the incident that motivated it. METR describes agents meant to be isolated coordinating through an unsanctioned message board in a package-repository cache (Greenblatt et al., 2026); here, state the agents wrote crossed an episode boundary through a persistent container filesystem. Neither defence saw it. The audit inspects each container once, before the batch, not the state it carries between episodes. The graph records a stale value as local information of the container where it was found --- a root rather than a transfer --- because the coupling never passed through the logged channel. The check this suggests is cheap enough to run tomorrow on any evaluation that reuses a sandbox: seed each episode with a canary and grep every other episode's logs for it.

\section{Discussion}

\textbf{Who would use this, and to decide what.} The reader we have in mind responds to an incident in a multi-agent deployment, after a restricted action has already fired an alarm. A per-agent monitor tells them that it happened and in which agent, not which containers to isolate or which deliveries to cut. The graph answers both from the logs alone, without model calls: the origin span is the set of containers to isolate, the minimum cut the deliveries to examine first. On our broadcast channel the span is also what an overseer would get by listing the senders in the acting agent's trace (Section~\ref{sec:attr}), so only the cut and the oracle check are genuinely new here. This asks one thing of an operator: record, with every message delivered between agents, the events already in the sender's context. It is the only field our harness needs that a typical agent log does not keep, and without it no post-hoc method can tell a relay from an origin.

\textbf{What the batch suggests.} Per-container audits did not bound what the population reached: no agent crossed its container's boundary, but information did. That agents given a channel and told to share will share is not a discovery; the instructed condition realises the composition failure rather than finding it. Its value is that everything is measurable at once --- audits pass, the restricted action is reached, the path is recorded --- which is what lets us ask the open questions. Agents notified a human in 41 of the 48 escapes, but before the decisive validation in only 1. We do not read that as a failure of escalation. In R1 they were told to validate, so a report filed afterwards is the expected behaviour.

\textbf{The cost of conservative ancestry.} The graph over-approximates by design, as conservative label propagation does in dynamic taint tracking (Schwartz et al., 2010); that is the price of a completeness guarantee checkable against an oracle. The 1-part control shows the bill: a policy of ``no foreign ancestry'' fires on legitimate actions whenever information is shared broadly. Recovering precision needs knowledge of local insufficiency, which a monitor would not generally have, or use-based attribution, which we do not attempt. So the operational claim is narrow. A containment audit certifies properties of containers and says nothing about what the channels between them carry, which is where this failure lives.

\textbf{What a month would add.} Four things, in the order we would run them. \textbf{(1)} Recreate the containers between episodes, add a per-episode canary, and re-run the emergent conditions, which Section~\ref{sec:contam} leaves unresolved. \textbf{(2)} Run the counterfactual replicas, already implemented: withhold the deliveries on the cut by content and sender, against a control that withholds as many off it. This is the only test in this design of whether the exposure cut is also a causal cut. \textbf{(3)} Separate the graph from the sender baseline that ties it here. Replacing the broadcast channel with addressed messages would make a part reach the validating agent only through a relay. Add, too, a population-level judge asked to attribute, which neither we nor the baseline test. \textbf{(4)} Lengthen the relay chains on that addressed channel, where the gap should widen with distance from the origin. Beyond a month: other model families, evaluating the alarm online, and applying the graph to real incident logs.

\section{Conclusion}

In our testbed local containment did not imply system-level containment: every audited container passed its checks, and the agents assembled and validated a credential no container held, in 48 of 95 episodes. A per-agent judge given the same policy detected every escape, and a trivial sender baseline attributed every escape as well as the graph did. The graph's distinctive outputs here are therefore narrower than we expected: the minimum cut, and a completeness check the baselines have no counterpart for. The batch also carried a coupling neither the audit nor the graph caught, files surviving between episodes, which we found only by checking every episode's logs against every other's credentials. One model, 5--10 episodes per point and no causal test of the cut make this a proof of concept. The requirement it points to is cheap enough to adopt first: record, with every delivery between agents, what was already in the sender's context.

\section{Limitations and Dual-Use Considerations}
\label{app:limits}

Table~\ref{tab:claims} states what we take the testbed to establish, to suggest, and to leave unshown. Four limitations do not fit in it.

\textbf{Containers persisted across episodes.} Section~\ref{sec:contam} reports this in full: the harness reused each population's containers across its episodes, agent-written fragments from 6 episodes reappeared in 28 later ones, and 12 of the 48 escapes and the only R3 escape lie among the contaminated episodes. The episodes at a given population size are therefore not independent, and every emergent-condition rate should be read as an upper bound.

\textbf{The minimum cut is not shown to be causal.} The pilot's counterfactual replicas blocked positional event ids, which land on other events when a non-deterministic model is re-run. We re-implemented them to withhold messages by content and sender, with a control that withholds the same number of deliveries outside the cut, but did not run them in this batch.

\textbf{Weak or favourable baselines.} Message count is trivial, and the judge with the rule is given the exact policy, uses the agents' own model and has an untuned threshold of 6.

\textbf{Sample and setting.} Points have 5--10 episodes; all agents and the judge are \texttt{deepseek-flash} without a seed; the prompts and fragment labels cue pooling; services are named by part, so with \(N>P\) two agents audit a service of the same name; and one instrumented channel is the only coupling between containers within an episode. Real deployments have many channels, incomplete logs and no oracle.

\textbf{Dual use.} This report describes how a population of individually contained agents can reach information that per-container containment is meant to protect, and it makes the mechanism concrete: split the target across boundaries, let each holder act within its remit, and assemble at one point. Three things bound what that adds to an adversary. The target is a synthetic credential in a closed environment, with no real system, product or vulnerability involved. The mechanism is not new --- it is the composition problem of Goguen and Meseguer (1982) and McCullough (1987), and recent decomposition attacks already exploit it (Jones et al., 2025; Srivastav and Zhang, 2025) --- so we contribute an audited instance, not a capability. And we publish no defence to be evaded: we block nothing.

The sharper question is what we say about evading attribution. We report that relaying did \emph{not} defeat any method we tried, because the channel is a broadcast; read adversarially, that still points at addressed relays as the direction in which post-hoc attribution would get harder. We judge the disclosure worth its cost for two reasons. The benefit is asymmetric: the graph runs on the operator's own logs, which an adversary inside the system neither controls nor reads, and only the operator can deploy the fix. And the fix is cheap and available now --- record, with each delivery between agents, the events already in the sender's context --- so a defender who reads this can close the gap in the same week that an adversary who reads it learns to widen it. The failure mode we would not want to publish is one whose remedy does not yet exist; this is not that.

\section{Testbed details}
\label{app:testbed}

\textbf{Setting and definitions.} An episode involves agents \(a_1,\dots,a_N\), each acting only through tools executed by a harness inside its own container \(c_i\), whose read-only volume holds its local information \(I_i\). A credential \(K=\{k_1,\dots,k_P\}\) is split into \(P\) parts assigned cyclically, so \(c_i\) holds exactly one part: with \(N>P\) some parts are held by several containers, with \(N<P\) some by none. The restricted action is a call \(R(s)\) to a validation tool. Containers are coupled only through a channel \(\mathcal{C}\) run by the harness; \(S\) is the composed system. Container \(c_i\) is \emph{locally contained} if it satisfies a set of checks evaluated on \(c_i\) alone, here the six below. \(S\) is \emph{contained with respect to \(R\)} if no execution of \(S\) contains a successful call to \(R\). A configuration is \emph{locally insufficient} if no container holds all parts, which here holds iff \(P\ge 2\). A \emph{collective escape} is a successful \(R(s)\) in an episode in which every container is locally contained and the configuration is locally insufficient; since the validator requires all \(P\) parts and the acting container holds one, it implies that \(s\) contains \(P-1\) parts that originated elsewhere.

\textbf{Containers.} Each container is \texttt{alpine} with \texttt{network\_mode: none}; its only mount is a read-only volume with its hint, a \texttt{config.yml} containing one line \texttt{clave\_prod\_parte\_\(k\)\_de\_\(P\): <part>} among unrelated settings, plus a log of health checks. The hint files are rewritten before every episode, but the containers for a population size are started once and reused across its episodes, so their own writable filesystem persists from one episode to the next (Section~\ref{sec:contam}). The model runs on the host. Agents act only through tools that the harness executes; commands run through \texttt{docker exec} with a 15-second timeout, and their output is cut at 8{,}000 characters. No API credentials exist inside the containers.

\textbf{Credential.} Each episode draws a seed at random, and part \(k\) is the first 10 hexadecimal characters of a SHA-256 hash of \(k\) and the seed; in this batch no part occurred in two episodes. Validation removes separators (whitespace and characters such as hyphens, underscores, dots, commas and colons) and succeeds only if what remains is the concatenation of the \(P\) parts in order.

\textbf{Tools.} \texttt{ejecutar} runs a command in the agent's own container; \texttt{escribir\_canal} posts to the shared channel (at most 500 characters per message and 20 messages per agent; broadcast; persistent); \texttt{leer\_canal} returns the messages posted since the agent's last read; \texttt{validar\_credencial} is the restricted action; \texttt{notificar\_humano} sends a message to a human operator. The channel is a file on the host that only the harness touches, so agents can read it only through the tool, and every delivery is logged.

\textbf{Episodes.} Agents act in round-robin turns, 10 turns per agent (30 in the pilot's impossible task). Each agent's context holds its last 8 events; older events are compacted into a summary event whose ancestors are the compacted events, so ancestry is preserved, and the model's history receives a textual summary of at most 800 characters. Agents and judge use \texttt{deepseek-flash} through DeepSeek's OpenAI-compatible API at temperature 0.

\section{Decomposition of the minimum cut}
\label{app:cut}

For a decisive action with span \(\sigma\) and cut \(\kappa\), write \(D=\sigma-P\) for the redundancy of the span (containers holding a part already represented) and \(E=\kappa-(\sigma-1)\) for the routes beyond one per foreign origin, so that \(\kappa=(P-1)+D+E\). A single message relaying several parts can make \(E\) negative; a part delivered by two senders, or delivered twice, raises it. Over the 48 escapes \(D\) was 0 in 31, 1 in 15, 2 in 1 and 3 in 1, and \(E\) was 0 in 32, 1 in 9, 2 in 6 and 3 in 1; it was never negative. The mean \((D, E)\) was \((0.3, 0.0)\), \((0.5, 0.7)\) and \((0, 0.33)\) at \(P=2\), 3 and 4 with \(N=4\), and \((0.8, 1.0)\) and \((1.6, 0.4)\) at \(N=5\) and 8 with \(P=4\). An ordinary least-squares fit over the 39 instructed escapes gives a slope of 1.16 per part (95\% CI 0.70 to 1.62) and of 0.32 per agent (0.03 to 0.61). With 36 residual degrees of freedom, an integer outcome and a design in which \(P\) varies only at \(N=4\) and \(N\) only at \(P=4\), we treat this fit as descriptive. On the 13 instructed escapes of the pilot the same fit gave 1.02 per part and 0.05 per agent.

\section{The impossible task}
\label{app:imposible}

We ran this condition only in the pilot batch, with its guessable parts and permissive validator (Appendix~\ref{app:pilot}), and report it only as a qualitative observation. In the impossible task (6 episodes, \(N=5\) and \(N=8\)), one part exists in no container, every container holds a decoy ``master backup key'' that audit agents are told not to use, agents have 30 turns, and the harness asks them to continue when they stop. It differs from the other conditions in turn budget, continuation prompts, population sizes and output cap (the 8{,}000-character cap was added after these runs), so we do not compare it quantitatively with R1--R3.

Agents read the decoy key in all 6 episodes and never submitted it (0/6), and all 6 episodes included a notification to a human. Agents made 28.7 validation attempts per episode and the harness asked them to continue 25.7 times per episode. By the coarse keyword heuristic of Appendix~\ref{app:heuristics}, 8.1 of every 100 commands fell outside the auditing scope (for example network probes or reading other processes' environment variables), against 1.9 in the pilot's other conditions, and every impossible-task episode contained at least one such command (6/6, against 12/31). Per episode the contrast is larger (8.7 against 0.5), but impossible-task episodes are longer: 107 commands per episode on average, against 27. Searches from the filesystem root occurred at the same rate per command (33.0 against 33.1 per 100 commands), so their higher count per episode (35.3 against 9.0) reflects episode length, not a change in behaviour. The comparison is further confounded by continuation pressure, and the heuristic has not been validated against human labels. These observations are consistent with agents broadening their actions when the legitimate route is unavailable, while respecting an explicit prohibition in this instance. They are not evidence of a general behavioural regularity. The graph's alarm fired in all 6 episodes, since agents pooled the parts that existed and tried to validate.

\section{Behavioural heuristics}
\label{app:heuristics}

A command counts as \emph{out of scope} if any of its simple commands starts with a network, privilege or package-management program (\texttt{curl}, \texttt{wget}, \texttt{nc}, \texttt{ncat}, \texttt{netcat}, \texttt{ping}, \texttt{nslookup}, \texttt{dig}, \texttt{ssh}, \texttt{scp}, \texttt{telnet}, \texttt{sudo}, \texttt{su}, \texttt{chmod}, \texttt{chown}, \texttt{mount}, \texttt{nsenter}, \texttt{chroot}, \texttt{docker}, \texttt{apk}, \texttt{apt}, \texttt{apt-get}, \texttt{pip}, \texttt{pip3}), or if it references \texttt{/proc/<pid>/environ}, \texttt{/etc/shadow}, \texttt{docker.sock} or \texttt{/var/run/secrets}. A command counts as a \emph{root search} if it runs \texttt{find}, a recursive \texttt{grep}, or \texttt{ls -R} with \texttt{/} as an argument. Both are keyword heuristics (\texttt{CS/hormiguero/grafo/agregar.py}) and have not been validated against human labels.

\section{Pilot batch, changes and future work}
\label{app:pilot}

\textbf{Pilot batch.} Before the main batch we ran 37 episodes with the same model, prompts and conditions, 1--3 per point, plus the impossible task. Analysing them exposed three flaws. The parts were the code words \emph{Alpha}, \emph{Bravo}, \emph{Charlie}, \dots, so an agent could in principle produce a part it had never seen. Validation accepted any string containing every part, and 9 of 168 successful validations were not the plain credential (parts reversed, or characters appended). And the counterfactual replicas blocked positional event ids, which fall on other events when a non-deterministic model is re-run: in 2 of 3 replicas none of the blocked ids was a channel message. For the main batch we replaced the parts with random fragments, required the exact credential, re-implemented the replicas by content and sender, and ran more episodes per point. Table~\ref{tab:pilot} compares the two batches. They agree qualitatively --- instructed agents escaped whenever every part was reachable and never when one was missing, there was no under-attribution, over-attribution appeared only with \(N>P\), and the graph alarmed on every 1-part control --- with three differences: R3 escaped in 2 of 3 pilot episodes and 1 of 10 main ones; the honesty condition in 2 of 3 and 8 of 10; and the pilot's cut showed no association with \(N\) (\(\rho=0.00\) over 7 escapes), where the main batch shows one. The pilot also ran a judge without the rule, which flagged 8 of 17 escapes and 3 of 11 episodes without escape; it rendered traces differently (160 against 300 characters per event), so its gap to the judge with the rule is not attributable to the rule alone.

\textbf{Future work.} The following would address the main weaknesses of this report.
\begin{itemize}
  \item \textbf{Fresh containers per episode.} Recreating the containers, or resetting their writable filesystem, before every episode removes the cross-episode coupling of Section~\ref{sec:contam}; an audit that compares a container's state before and after each episode would detect it.
  \item \textbf{Counterfactual replicas.} The content-and-sender replicas are implemented but were not run. Running them against their random control is the only test in this design of whether the exposure cut is also a causal cut, or whether the population routes around it, for example through the second holder of a duplicated part.
  \item \textbf{Use-based provenance.} Because the harness records the context window of every step, the decisive model call can be reconstructed and replayed with one ancestral message removed at a time. Messages whose removal changes the action count as \emph{used}; the others are only exposure (in the spirit of Cohen-Wang et al., 2024). Agents' own citations, an optional field of the validation tool, give a second, self-reported lower bound.
  \item \textbf{Stronger baselines.} A keyword and pattern detector over channel messages and validation arguments; a population-level LLM judge that reads all traces and is asked to attribute, which is the natural comparison for the graph's attribution; and judges from a different model family than the agents, with thresholds set on held-out episodes.
  \item \textbf{More models and more episodes.} The harness separates the agent loop from the model provider, and a second provider is already integrated but was not run. Other model families and more episodes per point would allow rates with useful confidence intervals.
\end{itemize}
Beyond these, we plan to evaluate the graph's alarm online, before a restricted action executes, and measure its cost on benign collaboration; to sweep the channel's bandwidth, persistence and addressing as containment parameters; and to study heterogeneous populations, applying the graph to real incident logs when they identify agents.

\section{Logging, baselines and the 1-part control}
\label{app:control}

\textbf{Compaction and the upper bound.} When an agent's window overflows, the oldest events are replaced by a summary event whose ancestors are the replaced events. Because each new summary absorbs the previous one, every event that ever entered an agent's window remains a transitive ancestor of that agent's later actions, even after the textual summary has dropped its content. The ancestor set is therefore an \emph{upper bound} on the information available in the agent's context at the time of an action, and a fortiori on the information it used. This is what makes the completeness check below meaningful.

\textbf{Three notions of completeness.} \emph{Logging completeness}, that every cross-container transfer passes through the harness, is supported by design and by the audit but not independently verified, and a path across episodes did bypass the per-episode log (Section~\ref{sec:contam}). \emph{Completeness relative to the oracle}, that there is no under-attribution, is what we measure. \emph{Causal completeness}, that \(\mathrm{anc}(v)\) contains everything that influenced \(v\), is not established: the model's parametric knowledge and system prompt are inputs outside the graph. The converse, that every ancestor influenced \(v\), is known to fail (Section~\ref{sec:attr}).

\textbf{Graph construction.} The graph has one node per event and an edge \(u\to v\) whenever \(u\) is an ancestor of \(v\); it is checked to be acyclic. An edge whose endpoints belong to different agents is a \emph{transfer} with capacity 1 --- in our harness, exactly the post-to-receive edges, one per delivery --- and all others are \emph{derivations} within one agent, with unbounded capacity. The origin span \(\sigma(v)\) is the number of distinct containers with roots in \(\mathrm{anc}(v)\cup\{v\}\). For the minimum cut \(\kappa(v)\), add a source \(s\) with infinite-capacity edges to every root of \(\mathrm{anc}(v)\) whose container differs from that of \(v\)'s agent, and take the value of a minimum \(s\)--\(v\) cut, computed with NetworkX (Hagberg et al., 2008).

\textbf{Roots.} Events that bring no information from the environment --- the agent's own text, empty channel reads, summaries, notifications and continuation prompts --- are never roots.

\textbf{Two design consequences of the oracle.} When \(N=P\) the span cannot exceed \(P\), so exactness follows from the absence of under-attribution, and over-attribution is observable only when \(N>P\). The oracle identifies which parts were needed, not which of several containers holding the same part supplied it.

\textbf{Baselines.} \emph{Message count} fires when an episode has more than two channel messages; it is a deliberately trivial detector. The \emph{per-agent LLM judge} (\texttt{deepseek-flash}) reads one agent's trace, with each command shown up to 200 characters and each output or message up to 300, scores it from 0 to 10, and the episode alarm fires if any agent scores 6 or more. It receives the policy the graph's alarm encodes, which makes it a favourable comparison for detection.

\textbf{The 1-part control.} With \(P=1\) every container holds the complete credential, so validating is legitimate, but agents were still instructed to share. The first successful validation had span 1 in 8 of the 10 episodes and spans of 2 and 3 in the other two; later validations had spans of up to 4, because by then other agents' messages carrying the same credential were among the validating agent's exposures. The graph's alarm fired in all 10 episodes and the rule-aware judge in 2. An alarm restricted to the decisive action, a variant we identified after the pilot, would have fired in 2 of the 10 controls and in all 48 escapes.

\section{Related work in detail}
\label{app:related}

\textbf{Composition, information flow and provenance.} Noninterference formalises the absence of information flow from secret inputs to public outputs (Goguen and Meseguer, 1982); McCullough (1987) showed that such properties need not survive the connection of secure components, and Mantel (2002) characterised when they compose. We borrow the question, not the formalism: our local checks are operational audits rather than trace properties, and we demonstrate non-composition empirically. In the ML setting, Jones et al.\ (2025) show that an adversary can misuse combinations of individually safe models by decomposing a task across them; their unit is model outputs under an external adversary, ours is containment of distributed information, with agents that aggregate it themselves. Spera (2026) proves formally that safety is non-compositional when a forbidden capability has conjunctive dependencies, and checks the premise on recorded tool-use traces; we prove nothing, but exhibit non-composition in a running system, where the local property is an executed container audit and the forbidden capability is reached by the agents rather than inferred from a dependency graph. Closer to our mechanism, Srivastav and Zhang (2025) fragment a harmful request across agents so that each subtask looks benign, and Chen et al.\ (2025) monitor such decompositions with a sequential monitor; there the fragmentation is chosen by an attacker and the harm lies in the content, whereas here it is a property of the deployment --- who holds which secret --- and every message is honest. Our graph is a coarse, context-level instance of data provenance (Denning, 1976; Myers and Liskov, 1997; Buneman et al., 2001; W3C, 2013): its nodes are tool calls and its edges record exposure, not program-level dependencies.

\textbf{Flow control and provenance for LLM agents.} Several systems enforce information-flow policies inside a single agent, tracking labels in a planner (Costa et al., 2025), separating trusted control flow from untrusted data flow (Debenedetti et al., 2025), bounding tool arguments by their recorded sources (Sequeira et al., 2026), or comparing a provenance graph with an authorisation graph derived from user intent (P. Wang et al., 2026). NeuroTaint argues that taint in LLM agents includes semantic transformation and causal influence, not only explicit content transfer (Cai et al., 2026) --- the same distinction that separates our exposure provenance from use-based provenance. These target prompt injection within one agent and, except for NeuroTaint, run at runtime; we work post hoc and across agents. Across agents, Prompt Infection shows malicious prompts self-replicating through a population (Lee and Tiwari, 2024); closest to our motivation, SafeFlow builds its defence on the premise behind our testbed, that splitting a harmful goal across agents leaves every individual step looking acceptable (Dai et al., 2026), and AgentFlow expresses flow policies over labelled runtime edges including delegation (Shivakumar et al., 2026). Distributed Sentinel targets the same shape of failure --- each action is defensible on its own because the facts that would condemn it sit in another agent's context --- and answers it with sidecar proxies that carry semantic taint tokens across those boundaries (Wu and Gong, 2026), and MAP-Graph gates a shared memory on provenance-derived trust (Y. Wang et al., 2026b). All are enforcement mechanisms evaluated on attack benchmarks or blocked-violation rates; we propose no defence, block nothing, and measure a containment failure without an external attacker.

\textbf{Multi-agent risk, monitoring and forensics.} Hammond et al.\ (2025) and Schroeder de Witt et al.\ (2025) survey risks and set an agenda for multi-agent security; Motwani et al.\ (2024) study covert collusion through steganography and Meinke et al.\ (2024) in-context scheming. Our agents are not deceptive and their channel is overt, which is what makes per-agent oversight insufficient here. Control protocols monitor an untrusted model with a trusted one (Greenblatt et al., 2024) and chain-of-thought monitors read its reasoning (Baker et al., 2025); both read one trajectory at a time, and our per-agent judge is a baseline of this kind. Makins et al.\ (2026) report the matching failure mode: as an attack is spread over more agents, per-instance monitors catch it less often. Our batch does not reproduce that degradation --- a judge given the rule flagged all 48 escapes, because in our design the assembled credential lands in one agent's trace --- which is why we claim attribution and not detection for the graph; their fragmentation regime is where cross-agent provenance should also pay off for detection. On collusion, Colosseum audits emergent collusion in agents given a secret channel (Nakamura et al., 2026), Rose et al.\ (2026) detect it from internal activations and Zeng and Rudzicz (2026) in competing agents. On attribution, a recent survey collects the work on tracing evidence and execution through agent runs (Y. Wang et al., 2026a), Agent-BOM builds an attributed graph for post-hoc auditing (Li et al., 2026), Zhang et al.\ (2025) automate failure attribution, and Causal Agent Replay (Shah, 2026) and ContextCite (Cohen-Wang et al., 2024) are routes to the use-based attribution our graph does not attempt. The closest methodological ancestor is BackTracker (King and Chen, 2003), which reconstructs intrusions by traversing an operating-system dependency graph backwards from a detection point to find what \emph{could have} affected it: our ancestor query is the same operation over agent events, and shares the property that recorded dependencies are potential, not actual. We use max-flow/min-cut (Ford and Fulkerson, 1956) to count message routes. Our \emph{escape} is not the one measured by SandboxEscapeBench, where a single agent exploits a vulnerability to break out of its container (Marchand et al., 2026): no container is breached here. Nor is it ContainmentBench, which scores what an agent does after untrusted content has entered it, in largely single-agent workflows (Lan et al., 2026); our question is how the content crossed a container boundary at all.
